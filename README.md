# 帯替えツール（AMUSE不動産）

他社の物件図面PDF（レインズ等からの一括ダウンロードで、複数社・複数物件が
1つのPDFに束ねられているケースを含む）を読み込み、ページ下部の「帯」
（元の仲介会社の会社名・連絡先ブロック）を自動検出して、AMUSE不動産の
帯に差し替えるための社内向けWebツールです。

従業員はブラウザでPDFをアップロードするだけで使えます（Pythonやコマンド
ラインの知識は不要です）。

## できること

- PDFをページ単位に自動分割し、ページごとに帯を差し替え
- 図面のタイプ（画像PDF／テキスト入りPDF、罫線の実線・点線など）を
  自動判定し、それぞれに適した方法で帯を検出
- 横向き・縦向きのページを自動判定し、対応する帯（横帯／縦帯）を使用
- 差し替え前後のサムネイルを並べて表示し、目視確認できるようにする
- 自動判定の信頼度（high / medium / low）を表示し、要確認ページを
  ひと目で分かるようにする
- 結合済み1ファイルとしてのダウンロード、またはページ別ZIPでの
  ダウンロードの両方に対応

## 動作の仕組み（band_logic.py）

1. **ページ分類**：ページ内のテキスト量で「テキストが十分にある
   （ベクターPDF）」か「ほぼ無い（画像PDF、または文字がアウトライン化
   されているPDF）」かを判定
2. **ベクターPDFの場合**：以下の優先順位で「帯」の領域を検出
   1. 会社名・住所・TEL等が1枚の画像として埋め込まれているパターン
      （画像のバウンディングボックスから検出）
   2. 罫線で囲まれた幅広のボックスがあるパターン（get_drawings()から検出）
   3. 上記で見つからない場合、TEL/FAX/株式会社などのキーワードの位置から
      推定（フォールバック、信頼度「低」として扱う）
   
   検出した領域を白塗り（redaction）した上で、同じ位置にAMUSE不動産の
   帯をベクターのまま重ね込みます（画質劣化なし）。
3. **画像PDFの場合**：ページ全体を画像としてレンダリングし、下部にある
   横罫線（実線・点線の両方に対応）を検出して帯の境界とし、その下を
   AMUSE不動産の帯に差し替えます。
4. ベクターPDFの検出に失敗した場合は、自動的に画像方式にフォールバック
   します。

既知の制約:
- テンプレートの多様性が非常に高いため、100%の精度は保証されません。
  自動判定の信頼度が `medium` / `low` のページは、必ず目視確認してから
  配布してください。
- 新しい配信元（テンプレート）で検出に失敗するページが出てきた場合は、
  `band_logic.py` の `ANCHOR_KEYWORDS` にキーワードを追加する、または
  `find_footer_box_by_border` / `find_band_top_row` のしきい値を調整する
  ことで対応できます。実際に失敗したPDFのサンプルがあれば、それを元に
  調整するのが最も確実です。

## 自社の帯を変更する場合

`assets/amuse_band_yoko.pdf`（横向きページ用）と
`assets/amuse_band_tate.pdf`（縦向きページ用）を差し替えてください。
帯の位置（`band_logic.py` の `BAND_CONFIG` 内の `clip` 座標）も
新しい帯のPDFに合わせて更新が必要です。座標の調べ方は、PDFをPyMuPDFで
開いて `page.get_drawings()` や `page.get_text("dict")` の結果を確認する
方法が簡単です（Claude等のAIアシスタントに新しい帯PDFを渡して
「clip座標を調べて」と頼むのが最も早いです）。

## ローカルでの動作確認

```bash
python3 -m venv venv
source venv/bin/activate   # Windowsは venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

ブラウザで `http://localhost:5000` を開いてください。

## 本番公開（デプロイ）について

GitHub自体はコードを保存する場所であり、実行環境ではありません。
以下のいずれかのサービスと連携してデプロイしてください（どちらも
無料枠があります）。

### Render.com を使う場合
1. このリポジトリをGitHubにpushする
2. Render.comで「New Web Service」→ 対象リポジトリを選択
3. Build Command: `pip install -r requirements.txt`
4. Start Command: `gunicorn app:app --timeout 120`
5. デプロイ完了後に発行されるURLを従業員に共有する

### Railway.app / Fly.io など
同様に「GitHubリポジトリと連携 → 自動でrequirements.txtとProcfileを
検出してデプロイ」という流れで動作します。

## ディレクトリ構成

```
band_app/
├── app.py              Flaskアプリ本体（ルーティング、アップロード処理）
├── band_logic.py        帯検出・差し替えのコアロジック
├── requirements.txt
├── Procfile              本番デプロイ用の起動コマンド
├── templates/
│   └── index.html        アップロード画面・結果画面（フロントエンドHTML/JS）
├── static/
│   └── style.css
└── assets/
    ├── amuse_band_yoko.pdf   横向きページ用の自社帯
    └── amuse_band_tate.pdf   縦向きページ用の自社帯
```

## セキュリティ・運用上の注意

- アップロードされたPDFの処理結果は、サーバーのメモリ上に一時保存され、
  60分後に自動的に破棄されます（`app.py` の `JOB_TTL_MINUTES`）。
  永続化はしていないため、サーバーを再起動すると処理結果は消えます。
- 社外に公開する場合は、簡易的なパスワード認証などを追加することを
  推奨します（現状は誰でもアクセスできる想定のコードです）。
